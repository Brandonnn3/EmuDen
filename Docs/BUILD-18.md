# Build 18 — save history and public information

## Save points

The pause menu keeps Quick Save / Quick Load and adds **Save history** with dates, top-screen thumbnails and confirmation before loading an older point. It retains the latest **10 manual** and **3 automatic** snapshots independently for each imported game and compatible core/system-resource revision. Existing quick/resume files remain readable; on the next successful save the previous file is archived before the latest slot is atomically replaced. Snapshots remain SHA-256 checked with bounded size and symlink validation. Loading a latest-slot selection that has since been replaced is rejected instead of silently restoring a different point. Retention deletes only recognized snapshot-history files, never native game saves or NAND/SD contents.

Automatic save points default on every five minutes of active play, configurable in Player settings. Capturing a point briefly pauses the core. Paused/menu time and background gaps do not accumulate normal active-play time. Background/exit capture remains enabled independently of the periodic toggle. Direct UIKit background/activation notifications supplement SwiftUI scene changes, with duplicate requests guarded per background transition. A background request now waits for an in-flight state operation, with a bounded wait and the system's background-task expiration handling. A force-quit, crash, storage failure or OS termination can still prevent completion; in-game saving remains important.

Startup offers the newest compatible snapshot, whether manual or automatic. The history screen explains that the game's own Save / Continue data is separate. Importing changed system resources or using a different core generation intentionally separates incompatible snapshots; the older files stay on disk and the UI explains their unavailable status. Reimporting a game as a different library file can also select a different state bucket; no claim is made that a missing snapshot on the owner's phone was recovered or that its precise cause was identified.

## Source and notices

Original EmuDen application, bridge, widget and build-tool contributions are now explicitly GPL-3.0-or-later under the owner's authorization, including those in build 17. Third-party licenses remain in force. LICENSE.txt and COPYRIGHT.md record the scope; game artwork, publisher characters/marks and Apple assets retain separate rights.

The notices generator preserves 84 full notice/license texts (or the complete leading MIT license comments for the two libretro headers), with source hashes and a machine-readable inventory. The app bundles this text for offline viewing from Settings. Public support, privacy and corresponding-source links are visible in the same section. Mii import guidance now refers to authorized decrypted console resources rather than recommending a named third-party installer. Import parsing and emulator graphics/core binaries are unchanged.

Matching source is published at https://github.com/Brandonnn3/EmuDen with source-only prereleases and independently verified anonymous downloads. The support/privacy/source Site is separate from the existing public artwork catalog. Only the explicitly authorized support email is public; private review contact, signing data, ROMs, system/Mii files, user saves and diagnostics are excluded.

## Verification and limits

See build/TestFlight/Build18-PreparationReport.json for final checks and artifacts. The full domain suite passes 62 tests; tooling checks pass two tests. Duo Simulator checks pass the manual history/load/relaunch flow, legacy quick/resume flow, offline notices and periodic capture after forced relaunch. A stricter Home-button background test demonstrates that the Duo Simulator leaves the app active on its other display, so it cannot certify that transition. A separate single-screen iOS 27.0 native integration check verifies a fresh background point after switching to Safari, with periodic saving disabled and at least 120 actual rendered Homebrew frames; its wrapper/payload checksum passes. The first 20-second poll ended before the Simulator completed the app switch/save, and the finished point was verified afterward. Secondary GUI retries encountered cold Simulator accessibility/toolbar timing; they are retained as failed results rather than counted as passes. The five-minute production interval is domain-tested; the short live periodic interval is Simulator-only. Domain tests cover independent history retention, legacy single-slot migration, restart stability, thumbnails, corrupt states, symlink escapes and active-play timing. Focused Simulator UI checks exercise actual Homebrew Menu state capture/restore, earlier-point selection, a new background timestamp, relaunch and offline notices. A Simulator-only short timer exercises the actual periodic capture/restore path; device builds keep the five-minute interval.

No new phone FPS gain is claimed. No physical B Duo test, native landscape/folding confirmation, App Store submission or TestFlight upload is performed as part of this preparation. The generated artwork and archived builds 14–17 are preserved unchanged. Public submission still depends on the unresolved records in TestFlight/AppStoreReadiness.json; source/policy publication is neither an IP clearance nor an Apple approval guarantee.

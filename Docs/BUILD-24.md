# Build24 — internal PlayStation testing

The owner resumed emulator development after the artwork repair. This branch, `multi-emulator-build24` in `/Volumes/SamsungT7/EmuDenMultiEmulator`, starts from frozen build23 (`6df10d7`), not the older unfinished build20 tree. It preserves build22's sanitized3DS/OpenSSL3 dependencies, age-service timeout, local/privacy policy and build23's optional catalog flow. Earlier archives/source packages, saves and generated masters remain untouched.

PlayStation phase one adds the pinned PCSX ReARMed interpreter, NEON software GPU, audio, digital-pad controls, gamepad mapping, per-game native memory cards and separate dated snapshot history/resume. Landscape controller play fills the display and hides touch controls; touch play reserves comfortable side space. Switching platforms tears down the previous core. No CPU JIT or proprietary BIOS is bundled. HLE is the default, with optional checked user-owned SCPH5500/5501/5502 BIOS imports.

Accepted PS1 formats are CHD v5, a flat folder containing exactly one CUE with every referenced BIN track, selection of that CUE and all tracks together, and PS-X EXE homebrew. BIN alone, ISO, PBP, M3U, disc swapping and analog-only games are outside this phase. Imports reject missing/ambiguous tracks, malformed headers, traversal and symlinks and roll back partial copies. Existing3DS files, native saves and snapshots retain their paths/formats. PS1 catalog matching is deliberately unavailable rather than matching a3DS title by name.

The original bundled4KB PS-X demo is generated by `Scripts/make-ps1-homebrew.py`. It contains original primitives, PAD input and an ADPCM tone. It and the separately licensed3DS demo are accessible without imported-game adult confirmation. No commercial game, Sony firmware or owner files are included in the candidate/source package.

GameCube research ABI/import/player code is retained behind native-framework availability, but **no GameCube framework or demo is embedded and no GameCube menu is available in24**. Build25 is the next development target, not a completed retail-GameCube build. The existing Dolphin prototype has only original VI/SI homebrew evidence; GX3D, audio, disc imports, native card writes and phone performance need further work.

## Rebuild

Use the exact matching source package. Restore the sanitized Azahar archive and the OpenSSL3/font/fallback sources as documented in BUILD-22.md. `python3 Scripts/build-ps1-core.py --target all` verifies all1,383 pinned source files and reconstructs the PS1 Host/Simulator/Device frameworks and genuine matching dSYMs from `Upstream/pcsx-rearmed-7b0e8f8-source.tar.xz`. It needs Python3, Xcode/Clang and make. Build24 adds95 full offline upstream/dependency notice texts. Device/Simulator PS1 frameworks do not reference ptrace/syscall/mprotect; the checked recipe disables dynamic recompilation and physical CD access.

Build with the Emulator Xcode scheme. `Scripts/archive-testflight.sh` makes a local signed development archive and validates frameworks, actual dSYM UUIDs, original assets, notices, privacy, entitlements and signatures. It refuses to overwrite an archive. `python3 Scripts/package-testflight-source.py` makes an allowlisted portable source package without games, personal resources, signing data, contacts or credentials. Neither script uploads anything. Local dependency symlinks are build conveniences, never package members.

Actual results/artifacts are recorded in [MULTI-24-PROGRESS.md](MULTI-24-PROGRESS.md). Public release remains held for the existing actual distribution/rights/privacy/export decisions and final device checks. Technical packaging does not establish legal clearance or Apple acceptance. TestFlight upload is a separate held action; a development archive alone is not a distribution-signed IPA.
